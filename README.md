# dispatcher_trainer_lab8

## Лабораторная работа 8

**Тема:** Элементы современного C++ для безопасной модели состояния.

**Вариант D:** диспетчер роботизированной линии.

## 1. Цель работы

Изучить и применить возможности современного C++ для безопасного представления состояния системы, обработки результатов операций и сохранения текстового журнала событий.

В лабораторной работе используются `std::optional`, `std::variant`, `std::visit`, `std::filesystem` и умные указатели.

## 2. Среда разработки

- VS Code и Docker Dev Container.
- C++20.
- CMake и Ninja.
- clangd и CodeLLDB.

## 3. Описание предметной области

Объект наблюдения — роботизированная линия. Программа представляет учебный тренажёр диспетчера, который отображает состояние роботов, зон безопасности, путей движения, предупреждений, аварийных сообщений и AR-подсказок.

Параметры варианта D:

- `robot_count` — количество роботов;
- `task_queue` — количество заданий в очереди;
- `safety_zone_state` — состояние зоны безопасности;
- `battery_level` — уровень заряда батареи.

Визуальные слои:

- `zone_map` — карта зон безопасности;
- `robots` — отображение роботов;
- `paths` — пути движения;
- `alarms` — предупреждения и аварийные сообщения;
- `ar_robot_marker` — AR-маркеры роботов.

## 4. Реализация возможностей современного C++

### 4.1. Использование `std::optional`

Для поиска параметра по имени используется метод `SimulatorCore::findParameter()`.

Результат представлен типом `std::optional<ParameterRecord>`. Если параметр найден, возвращается запись с его именем и значением. Если параметр отсутствует, возвращается `std::nullopt`.

Такой подход позволяет явно представить отсутствие результата и не использовать фиктивную запись параметра.

### 4.2. Использование `std::variant`

Для представления результата команды оператора используется тип `CommandResult`, основанный на `std::variant`.

Он может содержать один из трёх вариантов:

- `CommandOk` — команда выполнена успешно;
- `CommandWarning` — команда вызвала предупреждение;
- `CommandError` — команда завершилась ошибкой.

Метод `SimulatorCore::applyOperatorCommand()` возвращает соответствующий вариант результата. Например, команда для несуществующего параметра приводит к `CommandError`, а пустое новое значение — к `CommandWarning`.

### 4.3. Обработка результата с помощью `std::visit`

Для обработки `CommandResult` применяется `std::visit`.

Обработчик определяет фактический тип результата и выводит соответствующее сообщение:

- `[OK]` — успешное выполнение;
- `[WARNING]` — предупреждение;
- `[ERROR]` — ошибка.

Сообщения также записываются в текстовый журнал. Такой способ позволяет обрабатывать альтернативы `std::variant` без ручного определения активного варианта по индексу.

### 4.4. Сохранение журнала с помощью `std::filesystem`

Для работы с каталогом и путём к файлу используется `std::filesystem`.

Журнал сохраняется в файл:

`logs/session_log.txt`

Каталог `logs` создаётся при запуске программы. Метод `SimulatorCore::saveTextLog()` при необходимости создаёт родительский каталог и дописывает в файл сведения о событиях ядра: идентификатор, тип, приоритет и сообщение.

Класс `EventLog` дополнительно записывает начало и завершение сессии, а также результаты команд оператора.

Журнал имеет обычный текстовый формат. JSON, INI и сетевое взаимодействие для его сохранения не используются.

### 4.5. Использование умных указателей

В объектной модели применяются `std::unique_ptr` и `std::make_unique` для создания и передачи объектов в `DispatcherModel`.

Умный указатель обеспечивает автоматическое управление временем жизни объекта и освобождение ресурса при завершении владения. Это позволяет избежать необходимости вручную вызывать `delete`.

Для данной модели совместное владение объектами через `std::shared_ptr` не требуется, поскольку отдельные владельцы одного объекта в реализованном сценарии не нужны.

## 5. Объектная модель

В проекте используются следующие основные классы:

- `DispatcherModel` — хранение объектов модели и получение их описаний;
- `Robot` — робот и уровень заряда батареи;
- `SafetyZone` — зона безопасности и её состояние;
- `RobotPath` — путь движения робота;
- `Alarm` — предупредительное или аварийное сообщение;
- `ARRobotHint` — AR-подсказка, связанная с роботом;
- `ConsoleVisualRenderer` — вывод визуальных описаний в консоль;
- `SimulatorCore` — хранение и обработка параметров и событий;
- `EventLog` — запись текстового журнала.

## 6. Демонстрация работы

При запуске программа выводит описание объектов роботизированной линии, их визуальные представления и результаты проверки параметров. Затем отображается интерактивное меню ядра симулятора.

Меню предоставляет следующие операции:

1. Поиск параметра по имени.
2. Просмотр предупреждений и аварийных событий.
3. Просмотр событий, отсортированных по приоритету.
4. Просмотр статистики событий.
5. Вывод списка параметров.
6. Выполнение команды оператора.
0. Завершение работы.

При выполнении команды оператор вводит имя параметра и новое значение. Результат операции обрабатывается с помощью `std::visit` и выводится в консоль. Результат также сохраняется в журнале.

## 7. Сборка и запуск

Из корневого каталога проекта выполните:

```bash
./build/dispatcher_trainer
```

```bash
ctest --test-dir build --output-on-failure
```

## 9. Результаты работы

В лабораторной работе применены средства современного C++ для представления результатов операций и работы с файлами.

`std::optional` позволяет представить отсутствие найденного параметра, `std::variant` — один из нескольких результатов команды, а `std::visit` — обработать каждый тип результата. `std::filesystem` используется для создания каталога и работы с путём к текстовому журналу. `std::unique_ptr` обеспечивает автоматическое управление временем жизни объектов модели.

Таким образом, реализована обработка результатов команд диспетчера и сохранение событий учебного тренажёра в текстовый журнал.
